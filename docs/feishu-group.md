# 飞书群配置

把飞书群绑到某个项目后，群成员 `@机器人` 就能做只读排查或代码审查，结果回贴到同一条消息下面。一条绑定可以勾选多个环境；不写环境时走默认环境。

控制台入口：选中项目 → 左侧 **飞书群**。页面可新增、改开放环境 / 默认环境、删除绑定。改默认仓请删掉再建。一个 `chat_id` 全局只能绑一次，不能把同一群绑到多个项目。

## 1. 先具备这些

| 条件 | 说明 |
|---|---|
| 控制面已启动 | 默认 `http://localhost:8790/`，飞书必须能 POST 到事件地址 |
| 项目已建好 | 工具 Binding、Skill / Rule、模型可用；审查还要先在「代码仓」绑本地仓库 |
| 飞书企业自建应用 | 与登录可以是同一个应用，但群机器人必须额外打开 Bot |

本机 `8790` 飞书访问不到。开发环境用内网穿透（ngrok / Cloudflare Tunnel / frp）把公网 HTTPS 转到 `8790`。生产填真实域名。

## 不要用「群自定义机器人 / Webhook」

群设置里 **添加机器人 → 自定义机器人**，得到 `https://open.feishu.cn/open-apis/bot/v2/hook/…` 的那种，**不能用**。

那种机器人只能你 POST 过去往群里推消息，**收不到 @**，也没有 App ID / Secret，控制面的 `/api/feishu/events` 接不上。建好了可以删掉，Webhook 地址也不要贴到公开地方。

要用的是 **飞书开放平台上的企业自建应用**，给这个应用打开「机器人」能力，再把 **这个应用的机器人** 拉进群。

## 2. 飞书开放平台

打开 [飞书开放平台](https://open.feishu.cn/) → 对应应用。

### 2.1 应用凭证

**凭证与基础信息** 复制：

- `App ID`
- `App Secret`

写入控制面 `application-secrets.yml`（见第 3 节）。

### 2.2 打开机器人并拉进群

1. **应用能力 → 机器人** → 启用。
2. 把机器人拉进目标群（例如支付告警群）。
3. 确认群允许机器人发言。

### 2.3 权限

在 **权限管理** 开通并发布（企业自建应用通常要管理员审核）：

- 获取与发送单聊、群组消息
- 接收群聊中 @机器人消息
- 以应用身份发消息（回复用）

对应 scope 大致是 `im:message`、`im:message.group_at_msg:readonly`、`im:message:send_as_bot`。名称以开放平台当前文案为准。

### 2.4 事件订阅

1. **事件订阅 → 订阅方式** 选 **将事件发送至开发者服务器**（不要选长连接）。请求地址填完整路径：

   `https://<公网域名>/api/feishu/events`

   只填域名、不带 `/api/feishu/events` 时，飞书会打到控制台首页，报「Challenge code没有返回」。本机 `localhost:8790` 飞书访问不到，必须穿透；能配 HTTPS 就不要用裸 HTTP。

2. 添加事件 **接收消息** `im.message.receive_v1`。
3. **Verification Token** 复制下来，写入 `verification-token`。
4. **不要开启事件加密。** 当前实现按明文 JSON 解析；开放平台若填了 Encrypt Key，事件会变成密文，机器人收不到群消息。

只处理 **群聊** 且消息里 **@了机器人** 的事件。私聊、未 @ 的普通群消息会忽略。

## 3. 控制面密钥

新建 `application-secrets.yml`（该文件已 gitignore，不要提交）后填写：

```yaml
investigator:
  auth:
    feishu:
      app-id: cli_xxx                 # 登录或群机器人必填，两边共用
      app-secret: xxx                 # 同上
      bot-enabled: true               # 群机器人必填 true；只用登录则 false
      verification-token: xxx         # 群机器人建议填；不填也能收事件，但不校验来源
      encrypt-key: ""                 # 不要填；开放平台也不要开加密
      service-username: feishu-bot    # 可不改；须与用户页服务账号用户名一致
```

也可用环境变量：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_BOT_ENABLED=true`、`FEISHU_VERIFICATION_TOKEN`、`FEISHU_BOT_SERVICE_USERNAME`。

改 yaml 后重启 Java。

## 4. 服务账号 `feishu-bot`

群消息不走登录人，而是用这个本地账号发起排查 / 审查。

1. 控制台 **用户** 页创建一个账号，用户名必须是 `feishu-bot`（或与 `service-username` 完全一致）。
2. 角色勾选 **运维 OPERATOR**（需要「对话」「代码审查」权限）。
3. 保持 **启用**。这个号不必拿来登录页面。

缺账号或被停用时，机器人会回「未找到飞书 Bot 服务账号」或「已禁用」。

## 5. 控制台「飞书群」页

顶栏先选对 **项目**。表单里勾选的 **开放环境** 才是这个群能查的环境（决定读哪套 Binding），**默认环境** 是问句里没写环境时用的。和顶栏下拉可以不同。一个飞书应用、一个 `feishu-bot` 账号本身不限制环境。

| 字段 | 必填 | 填什么 |
|---|---|---|
| `chat_id` | 是 | 群 ID，形如 `oc_xxx`。一个 ID 只能绑一个项目 |
| 群名称 | 否 | 备注，例如「支付告警群」，只给人看 |
| 开放环境 | 是 | 可多选 `test` / `pre` / `prod`。群里指定的环境必须在此列表中 |
| 默认环境 | 是 | 未在话里写环境时使用。只能选已勾选的开放环境 |
| 默认排查方向 | 否 | 内置：`http-5xx`（接口/可用性）、`order-payment`（订单/支付）。留空则按问句自动判断 |
| 默认代码仓 | 否 | 审查时用。不选审查会尝试项目里的第一个仓，仍建议指定 |

点 **添加绑定**。已绑定群可在表格里改开放环境 / 默认环境，也可删除。旧绑定升级后开放环境等于原先那一个环境，需要多环境时在表格里补勾。

### 怎么拿到 `chat_id`

任选一种：

1. 机器人已进群后，在群里 `@机器人 测试`。未绑定会回「这个群还没有绑定项目」。到开放平台 **事件订阅 → 推送日志**，打开 `im.message.receive_v1`，复制 `event.message.chat_id`。
2. 用应用 `tenant_access_token` 调飞书 `GET /open-apis/im/v1/chats`，对照群名称。
3. 部分企业在群设置里能直接看到群 ID。

不要填群名、open_id、用户 ID。必须是 `oc_` 开头的群 `chat_id`。

## 6. 群里怎么说

必须 **@机器人**，否则不会进控制面。

| 说法 | 行为 |
|---|---|
| `@机器人 用户 123 订单没到账` | 排查（INVESTIGATE）。用绑定的 **默认环境** 和默认方向 |
| `@机器人 prod环境 用户 123 订单没到账` | 排查生产。也支持 `测试环境`、`预发环境`、`环境:prod`、`env:test` |
| `@机器人 审查 main..feature/pay 看回调幂等` | 代码审查。`基准..对比` 两个分支都要写 |
| `@机器人 prod环境 审查 main..feature/pay 看回调` | 审查时切到生产（须已勾选 prod） |
| `@机器人 审查 base:main head:feature/pay 看回调` | 同上，另一种写法 |
| `@机器人 新对话`（或 `重置` / `reset`） | 丢掉本群上次会话，下次 @ 开新对话 |
| `@机器人 hi` / 在吗 | 短回复打个招呼，**不会**开排查 |
| `@机器人 不错哦👍` / 谢谢 | 按夸奖/感谢回一句，**不会**说「这不像排查」 |
| `@机器人` 闲聊辱骂 | 引导补故障信息，**不会**说「收到，开始排查…」，也不跑工具 |

句首单独写 `test 环境 user 123…` **不会**被当成切环境，避免误伤「test 环境」这种自然语言。要切环境请写成 `prod环境`（码和「环境」紧贴）或 `环境:prod`。

指定了未开放的环境时，机器人会直接回「这个群未开放 xxx」，不会开排查。

同一群连续 @ 会接上一次会话。审查前请先在控制台把对应仓库、分支拉得动；没绑默认仓又没写出分支时，机器人会提示补全。

## 7. 一次走通检查

1. 开放平台事件地址校验通过（保存请求网址不再报错）。
2. Java 已重启且 `bot-enabled: true`。
3. `feishu-bot` 用户存在且启用、角色含 OPERATOR。
4. 控制台该项目已有 Binding / Skill，审查还要有代码仓。
5. 「飞书群」列表能看到刚加的 `oc_xxx`。
6. 群里 `@机器人 ping 一下网关 5xx`，先回「收到，开始排查…」，稍后贴报告。夸奖/感谢应回一句口语，不要开排查；辱骂应直接引导，不要开排查。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 保存事件地址失败 | 公网必须打到 `/api/feishu/events`。本机穿透后填 `http://<穿透域名>/api/feishu/events`（不要只填域名）。飞书更稳的是 HTTPS；花生壳 HTTP 多数能过校验 |
| 飞书登录报 20029 / 重定向 URL 有误 | 开放平台 **安全设置 → 重定向 URL** 未登记回调。穿透时填 `http://<穿透域名>/api/auth/feishu/callback`，并用这个域名打开登录页，不要用 `localhost`。本机直连则填 `http://localhost:8790/api/auth/feishu/callback`。不要填事件地址 `/api/feishu/events` |
| @了没反应 | 确认 @ 的是开放平台这个应用的机器人（本应用显示名可能是「某某的智能助手」）。事件订阅必须是「开发者服务器」且地址带 `/api/feishu/events`，**改完事件/权限必须发版**。IDEA 控制台应出现「飞书事件到达」 |
| 闲聊也回「开始排查」 | 当前版本会先规则、再模型过滤。夸奖/感谢应回一句口语；短问候打招呼。若仍误伤真实故障，把原话记下来 |
| 夸奖却回「这不像排查」 | 已按夸奖/感谢单独回复。重启控制面后再试「不错哦」 |
| 回「这个群还没有绑定项目」 | `chat_id` 填错，或绑在了别的项目 |
| 回「未找到飞书 Bot 服务账号」 | 用户页创建 `feishu-bot`，用户名与配置一致 |
| 事件有推送但代码当空事件 | 开放平台开了加密。关掉加密，`encrypt-key` 留空 |
| 能收不能回 | 缺发消息权限，或机器人被禁言 |
| 审查让补分支 | 消息写成 `审查 main..feature/xxx`，并在绑定里选默认代码仓 |
| 排查查不到库 | 当前用的环境下没有启用对应 MCP；方向填错（`order-payment` / `http-5xx`）。问句没写环境时走默认环境 |
| 回「这个群未开放 prod」 | 绑定里没勾选该环境；到「飞书群」表格里补勾，或改用已开放环境 |

飞书登录（页面上的「飞书登录」）和群机器人共用 `app-id` / `app-secret`，但是两套能力：登录走 OAuth 回调 `/api/auth/feishu/callback`；群消息走 `/api/feishu/events`。只配登录、不配本节，群里 @ 不会工作。

## 9. 控制台「飞书登录」

授权链接里的 `redirect_uri` 跟你**打开登录页的域名**走。有内网穿透时，用穿透地址打开控制台，不要用 `localhost:8790`。

开放平台 **安全设置 → 重定向 URL** 把你实际会用的回调都加上（可多条）：

```
http://gf3032rm5129.vicp.fun/api/auth/feishu/callback
http://localhost:8790/api/auth/feishu/callback
```

群机器人事件订阅（另一处，不是重定向 URL）填：

```
http://gf3032rm5129.vicp.fun/api/feishu/events
```

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 选中 **App ID 与 `application-secrets.yml` 里 `app-id` 同一个应用**。
2. 登录：安全设置 → 重定向 URL，逐字添加上面的 callback，不要末尾斜杠，不要漏路径。
3. 群消息：事件订阅 → 请求网址填 events 那条。保存校验应通过。
4. 浏览器打开 `http://gf3032rm5129.vicp.fun/`（映射到本机 `8790`）再点「飞书登录」。

换穿透域名后，开放平台里的两条 URL 一起改。Java 会按当前访问的 Host 拼 callback，一般不用改 `FEISHU_REDIRECT_URI`。
