# 对话排查编排重构（Java + 真 Graph + MCP 工具面）

目标：把对话排查从「线性四节点 Graph 包一个黑盒 `ChatClient` 工具循环」重构为「结构化状态驱动的循环 Graph + 只读工具面单一来源」，以 Java/Spring 为主、复用现有 `StateGraph` 与只读工具。

## 已落地（Phase 1–2）

### 结构化状态与报告（`sre-investigator-graph`）
- `graph.state.InvestigationState`：跨轮累积 evidence / hypotheses / toolLedger（去重）/ openQuestions / 预算 / 迭代数；`toContext()` 回喂下一轮。
- `graph.state.{EvidenceItem,Hypothesis,ToolCallRecord,Confidence}`：证据/假设/账本的结构化条目。
- `graph.report.{StructuredReport,ReportMarkdown}`：四段结论的结构化 schema 与 Markdown 互转；`render` 始终包含「已确认的证据」保持向后兼容，`parse` 尽力从既有四段文本还原结构化字段。

### 循环 Graph（`InvestigationGraph`）
- `investigate ⇄ decide` 条件边（`addConditionalEdges` + `AsyncEdgeAction`）替换原 `investigate → synthesize` 直线。
- `decideNext(state, controlPlane, maxIterations)`：模型已给四段 / 预算耗尽 / 达到 `max-iterations` / 点名 MCP / 子 Agent → `done`；否则 `continue`。
- state 通道新增：`investigationState`、`iteration`、`widenProfilesByKind`、`reportStructured`。
- 软门控：方向白名单只作用第一轮；后续轮次放开到本环境全部已启用 Binding（`widenProfilesByKind`），解决「开局锁死、中途够不到日志/数仓」。
- `BusinessFlowExecutor.singleRound(..., extraContext, override)`：循环轮次回喂累积上下文、按需扩种类；子 Agent 业务流程图仍单轮内部分步。

### 模型韧性（`ResilientModelCall`）
- 对三处模型调用（investigate / ask / review / 结论补写）加重试 + 指数退避，配置 `investigator.agent.model-max-attempts`（默认 2）、`model-retry-backoff-ms`（默认 500）。
- 同线程重试，保住 `AgentThoughts` 的 ThreadLocal sink 与工具进度事件；超时交给各模型 HTTP 客户端。

### 结构化结果呈现
- `synthesize` 解析出 `reportStructured` 随 state 上浮。
- SSE 新增 `evidence` 事件（`InvestigationStreamController`）在 `result` 前推送结构化四段。
- 前端 `liveSession.ts` 消费 `evidence` + `result.state.reportStructured`；`InvestigatePage` 用 `MarkdownView` 渲染报告，并在最后一条助手消息下渲染证据/假设/排除/下一步面板（`EvidencePanel`）。

### 配置
- `investigator.agent.max-iterations`（默认 3）、`model-max-attempts`（默认 2）、`model-retry-backoff-ms`（默认 500）。

### 测试
- `InvestigationStateTest`、`ReportMarkdownTest`、`InvestigationGraphDecideTest`、`CyclicGraphSmokeTest`（验证图库接受条件边自环并正常终止）、`ReadonlyToolCatalogTest`。

## MCP 工具面（Phase 3：已埋接缝，传输待接线）

- 已交付接缝：`mcp.ReadonlyToolCatalog` 作为只读工具名的**单一事实来源**（35 项，按 `ToolKind` 归档），`InvestigationAgent.capabilities()` 改从它取，删除重复硬编码清单。
- 待接线（需真机验证启动与传输，本轮未做，避免破坏在跑的生产工具）：
  1. `sre-investigator-boot` 引入 `spring-ai-starter-mcp-server(-webmvc)`。
  2. 按 `ReadonlyToolCatalog` 把 `Readonly*Tool` 暴露为 MCP 工具，入参显式带 `projectId/environment/profile`（或 sessionToken 解析上下文）。
  3. 编排端经现有 `spring-ai-starter-mcp-client` 统一发现内外工具；客户端装饰器统一预算 / `ToolThought` / `AuditTrail` / profile 过滤。
  4. 灰度：`spring.ai.mcp.server.enabled` 默认关，验证通过再切编排端从进程内 `FunctionToolCallback` 到 MCP client。

## SSE 事件协议（现状）

| event | 时机 | 载荷 |
|---|---|---|
| `phase` | 控制器预发 / 图阶段 | `{name?, message}` |
| `started` | 会话与 run 落库 | `{conversationId, runId}` |
| `thought` | 工具/模型/步骤进度 | `{kind, message}`，kind ∈ tool/model/phase/evidence/think |
| `heartbeat` | 每 8s 保活 | `{ok:true}` |
| `evidence` | synthesize 后、result 前 | 结构化四段 `{phenomenon, confirmedEvidence[], ruledOut[], hypotheses[], nextSteps[]}` |
| `result` | 整轮结束 | `RunOutcome`（含 `result.state.reportStructured`） |
| `error` | 失败 | `{message}` |

## 遗留 / 后续

- 真正的 token 级流式（`ChatClient.stream()`）：受工具循环 + ThreadLocal sink 限制，本轮未做；已用 `evidence` 结构化事件 + 证据面板改善「干等」体验。
- ASK/REVIEW 仍是 code-only 单轮入口，未并入循环 Graph（它们不需要 route/load_context/loop）；已消除 `BusinessFlowExecutor` 单轮重复分步。
- 旧巨型 user prompt 一层堆叠仍在；进一步分层（System=政策+Rule，User=Brief+预读）留待提示词专项。
